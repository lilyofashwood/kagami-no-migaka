The chosen display title is **Kagami-no-Migaka**, with the exact companion description **かがみのしきしのみがか**. The selected source address is [lilyofashwood/kagami-no-migaka](https://github.com/lilyofashwood/kagami-no-migaka). Historical **Kasaneuta · 重ね歌** remains the method name.

## Evidence and interpretation

Lily of Ashwood originated the project; recovered artifacts document model-assisted development. The structural demonstration is a new implementation fixture, not an original poem.

The Nekomata specimen is the exact selected recovered grid, including **R=歌**. Its corrected second path is `AFKPU / BGLQV / CHMRW / DINSX / EJOTY`. The erroneous historical path repeats M and omits O; the recovered successful branch uses the corrected geometry. Both exact readings are regression-tested. Readings and poetic interpretations are not interchangeable, and no fluent-language approval or model-behavior benchmark is claimed.

The Kitsune specimen comes from the supplied **狐火重ね詩 — Kitsune Kasaneuta** React artifact, whose original SHA-256 is `8aef3136a8e967753e279d7a471467c647281e2f06d71e5da644013e2bf83354`. Only its grid is used here. Its two traversals are checked against separately specified strings. Its English glosses are supplied literary interpretation; this workbench does not present them as verified translations.

Earlier 4×4 and 5-row × 4-column experiments remain distinct from this application's fixed 5×5 document contract. They are not silently padded or relabeled. The present tool is not an implementation of every historical experiment.

## Local source boundary

Full documentary sources remain local and are not application assets. Obsolete source/chronology files in `historical/` are retained physically but ignored and untracked. Existing ignored `private-source/` copies remain untouched. Current-copy cleanup does not sanitize earlier Git history; publication requires a separately reviewed clean history. No raw handoff transcript is imported into the public tree.

## New implementation decisions

Explicit coordinate paths, one-visible-grapheme cells, strict malformed-input checks, safe DOM rendering, literal/semantic separation, a separate optional exact-byte envelope and a loopback provider adapter are implementation decisions. General grapheme mode is broader than the historical single-kanji construction profile. The generator follows supplied intentions without requiring one particular creature or identity.

The complete 78-entry [Font Garden](https://github.com/lilyofashwood/font-garden) catalog is vendored in `lettering.js`. It styles only authored interface text; grid cells, inputs, literal receipts, code and payloads are excluded. Plain accessibility labels remain available. The catalog retains original map and new-recipe attribution internally.

Only the dedicated loopback server injects the non-secret `layered-song-local-adapter` marker. Static pages disable provider actions and key entry. There are no automatic provider calls or capability probes. Origin checks remain in force; the marker is a UI capability indication, not authentication.
